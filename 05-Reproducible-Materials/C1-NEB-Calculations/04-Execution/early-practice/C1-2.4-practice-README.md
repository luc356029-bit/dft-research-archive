# C1 2.4｜3.实践

本包只摘取已完成的 LiSi path 0。复用原始结果，不提交新计算、不改写原始数据。

## 本次先做：结构与参数对应

打开 `path0_CI/INCAR`，找 IMAGES、LCLIMB、SPRING、EDIFF、EDIFFG、NSW。
再打开 `path0_CI/00/POSCAR` 和 `path0_CI/01/POSCAR`，核对元素、原子数和坐标段。无需逐行比较63组坐标。

`00` 是初态，`01—04` 是4个中间构型，`05` 是末态。每套结构均为31 Li＋32 Si。
IMAGES=4只计中间构型，不计初末态。目录编号不是优化迭代次数。

用一句话说明：本次有几套结构、哪些参与优化、电子计算和路径优化分别用什么条件停止。

## 当前文件处于哪一阶段

本项目实际链路：端点 → 线性插值后IDPP改善初始带 → 普通NEB → 继续CI-NEB → 收敛核查。
`path0_CI` 是正式四路径模型中path 0采用的四图CI结果，不是6图加密结果。
本段POSCAR是CI开始时的输入（来自普通NEB已优化带），不是最早的直线插值。
原始准备记录和参考源码在 `原始核验记录/`；暂不运行这些依赖原工作区的生产脚本。

本段INCAR：IMAGES=4，LCLIMB=.TRUE.，SPRING=-5，EDIFF=1E-7，EDIFFG=-0.02，NSW=24。
NSW是本段优化步数上限，不是已经完成的步数。EDIFF单位为eV/整个计算体系。
负EDIFFG用其绝对值作为力阈值；NEB验收要看相应投影/有效力，不把普通图像的全部真实力要求为零。

## 后续：提取能量、复算与核验

OUTCAR是原始文本输出，vasprun.xml是结构化原始输出，neb_analysis.json是后处理记录；证据优先级不能倒置。
00、05内OUTCAR是准备NEB时从独立端态计算复制来的，端态不是在本次NEB中再次优化。
01—04的POSCAR是本段输入，CONTCAR是本段输出；本例原审计已核对其与最后已评价XML构型一致，其他计算不能一概假定。

要在本目录终端中复算：`py 核查能量.py`。该脚本只读文件、只使用Python标准库，不调用VASP，也不写回原始结果。
统一提取完整离子评价帧的Efr/TOTEN，并与XML末帧对照。不要从电子自洽内部迭代随意挑一个TOTEN；也不要混用Efr、无熵能和E0。
Efr是本轮既有电子展宽能量口径，不是已经计入晶格振动熵的有限温度迁移自由能。

先自行算 E峰−EA、E峰−EB。与历史报告比较时注意：原模型在完整端态对称关系验证后，用E峰−(EA+EB)/2做数值对称化。只有几微eV的差异，不应误判为读错能量。
脚本成功只证明能量读取/一致性检查通过，不等于重新完成所有收敛、缺陷模型、路径覆盖和尺寸验证。

原有收敛检查参考：`原始核验记录/neb_analysis.json` 的 history最后一项、final_projected_force_gate_passed和final_CI_raw_force_gate_passed。
本段全带最大投影力约0.010787 eV/Å，满足0.02门槛；不能声称满足0.01的全带门槛。更严格四图、六图另有独立控制，不混入本练习。

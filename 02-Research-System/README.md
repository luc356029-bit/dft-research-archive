# 02 · 科研学习系统

本项目以**学习计算材料研究方法**为核心目标。系统按研究任务组织知识、按目标分配学习深度，并在每个小单元内完成理解、实践和反馈。

## 1. 系统构建前的问题

**1. 结构不清晰**。论文的叙述顺序与实际执行顺序不完全一致，AI 生成的脚本也常混合材料机制、计算方法和编程语法。缺少整体框架时，逐行学习容易混淆知识层次，笔记也难以组织和追溯。

例如，脚本按 a → b → c → d → e 执行，但 a、c、e 属于一个知识体系，b、d 属于另一个。照着代码顺序学习，就会在前一个体系尚未理解完整时切换到另一个，挤占思考空间。**脚本的执行顺序，不等于知识的学习顺序**。

**2. 没有主次**。缺少学习深度与重点的判断标准时，注意力容易转向代码语法等细节，在次要问题上持续深挖，偏离研究目的。

**3. 形成闭环慢**。知识体系频繁切换、任务拆分过大，会延长理论学习与实践之间的间隔。反馈推迟，不同问题容易停留在部分理解、尚未检验的状态。

上述问题的因果关系如下：

```math
\begin{gathered}
\begin{gathered}
\text{结构不清晰}\\[4pt]
\downarrow\\[4pt]
\text{知识混杂、频繁切换}\\[4pt]
\searrow
\end{gathered}
\qquad
\begin{gathered}
\text{缺乏主次判断}\\[4pt]
\downarrow\\[4pt]
\text{次要问题投入过多}\\[4pt]
\downarrow
\end{gathered}
\qquad
\begin{gathered}
\text{任务拆分过大}\\[4pt]
\downarrow\\[4pt]
\text{理论与实践间隔过长}\\[4pt]
\swarrow
\end{gathered}\\[8pt]
\text{理解、实践与反馈的闭环变慢}\\[4pt]
\downarrow\\[4pt]
\text{知识零散、难以追溯，项目推进越来越困难}
\end{gathered}
```

## 2. 建立在第一性原理和帕累托法则上的系统

### 2.1 从项目目的决定学习深度

先判断哪些理解直接关系到研究目的，再把精力集中在这些关键部分。

| 学习深度 | 具体内容 |
|---|---|
| **重点学** | 材料内部的机制；如何把材料信息转化为所需数据；所用方法、工具的基本运作方式、核心算法与数据流 |
| **稍微了解** | 工具更底层的运行原理、常用语法 |
| **放手** | 大部分代码语法与实现细节，交给 Agent 执行 |

实现细节可以委托，**科研目的、核心算法、数据流与结果检验仍需由研究者掌握**。学习深度以能否理解当前问题、判断结果为准。

### 2.2 工程线推进项目，筑基线补足基础

**工程线主导项目推进**。任务拆分框架包括候选筛选、结构与路径分析、NEB/AIMD、数据分析四个大板块，各板块再拆成逻辑相对独立的小单元。以一到两天完成一个单元为参考，让理解、实践和反馈尽量围绕同一个问题展开。

**筑基线主导系统性知识学习**。工程线完成一个相对独立的单元或板块后，再视具体情况决定是否转而推进筑基线。工程线中记录的问题可作为后续系统学习的参考。本节聚焦工程线，筑基线的独立学习记录未展开。

### 2.3 Agent + 工作流 + 项目文件

| 组成 | 在系统中的作用 |
|---|---|
| **Agent** | 讲解、试错、编写和执行代码、整理结果 |
| **工作流与项目提示词** | 明确当前目标、学习深度和反馈方式，使协作围绕同一问题推进，及时收回偏离重点的讨论 |
| **项目文件** | 保存研究背景、方法、参数、已有结果和待解问题，减少重复说明，便于核对和继续推进 |

每轮结束后，将确认的结论、证据位置和待解问题更新到项目记录中，为下一轮提供依据。

### 2.4 系统怎样运转

以 [A 初筛的工作流记录](../04-Learning-Notes/01-Research-Workflow/A初筛（方法论示范）.md)为例，可以概括为五步：

1. **定位与定目标**：先熟悉论文概貌，明确当前阶段为什么做、与前后步骤怎样衔接。
2. **形成方案并拆分**：由 Codex 先行试错，得到符合验收条件的方案，再拆为逻辑相对独立的小块，预估推进时间。
3. **理解核心知识**：由 LLM 讲解当前任务的核心知识并答疑；学习者据此整理理解模型，再借助 LLM 检查和修正。剩余问题留到实践中解决。
4. **实践并检验**：运行代码或分析已有输出，观察数据如何变化，结合论文、官方说明与计算证据检验结果。报错、疑问和论文差异随过程记录；NEB 等高成本计算可复用已有结果。
5. **反馈与推进**：将发现的问题带回方案或理解环节修正并完成检验。相对独立的单元或板块完成后，视具体情况选择继续工程线或转而推进筑基线。

在 A 初筛中，这体现为理解筛选依据、查询并筛选材料、保存清单与结构，再将论文差异追溯到具体材料条目和筛选条件。原记录中的斜体文字说明工作流，[05 · A 阶段](../05-Reproducible-Materials/A-High-Throughput-Screening/README.md)提供对应代码与输出。

**工作流随具体问题调整**。[C1 2.6](../04-Learning-Notes/02-Stepwise-Learning/C1/C1%202.6处理、对比.md)以数据处理、受控对照和差异分析为主，就围绕这些问题组织推进。

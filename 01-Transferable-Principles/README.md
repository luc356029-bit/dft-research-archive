# 01 · 可迁移的底层逻辑

**从根本目标出发，把任务逐层拆到可以执行，再用现实反馈修正方法与方向。** 这套系统将项目实践中的方法整理为三个层面：核心驱动确定目标与判断依据，系统架构组织推进，具体执行支撑日常行动。

## 主干—分支模型

![主干—分支模型：项目目标从下向上分为阶段目标与具体任务，执行反馈返回方法和目标](../assets/trunk-branch-model.svg?v=cb943fa1735a)

**主干是项目的根本目标，分支是阶段目标与推进方法，叶是具体任务。** 树形结构表示从整体到局部的展开关系；反馈则从执行返回方法，必要时进一步返回目标。

| 层面 | 主要解决什么问题 | 使用的方法 |
|---|---|---|
| [核心驱动](01-Core-Drivers.md) | 为什么做，什么最重要，出现问题后怎样修正？ | 五步法、第一性原理、帕累托原则 |
| [系统架构](02-System-Architecture.md) | 先推进哪里，怎样拆分，何时实践或调整？ | 方法论先行、快速反馈、系统一般可用原则、拆分法 |
| [具体执行](03-Execution.md) | 如何理解信息、恢复状态，并在任务间保留思路？ | 笔记法、休息原则、思路存储 |

三层按主要功能划分。**核心驱动贯穿全程**：第一性原理不断检查行动是否服务于根本目的，帕累托原则决定各层的投入重点，五步法推动整个系统改进。拆分也会在具体任务中继续使用。

## 从展开到修正

开始一个项目时，先明确根本目标，再形成足以启动的方法，拆出当前可以完成和检验的任务。执行中，根据问题所在的位置调整：

- **信息没有理解、思路中断或状态下降**：先处理具体执行问题。
- **同类问题反复出现、任务难以衔接或投入长期偏离预期**：检查推进方法与任务划分。
- **路线可以走通，但结果已不服务于根本目的**：重新审视项目目标及其与长期价值追求的关系。

这套系统在 DFT 复刻中的应用见 [02 · 科研学习系统](../02-Research-System/README.md)：以学习研究方法为目标，分配学习深度，再围绕相对独立的任务完成理解、实践与反馈。
